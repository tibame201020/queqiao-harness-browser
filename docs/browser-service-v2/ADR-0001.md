# ADR-0001 — Standalone HTTP Service, Harness backend

Status: proposed, 2026-10-29.

**Decision:** Browser Service is an independently deployable HTTP server. Existing Browser Harness is its first private execution backend. Pi, Paperclip, OpenCode, n8n and Queqiao may call it but are not required for server startup or correct behavior.

**Trade-off:** Direct Harness config/Runner integrations force every client to understand browser sessions and site providers. Expanding the Queqiao extension would preserve that deployment dependency. The independent HTTP seam centralizes client authentication, Operation identity, idempotency and normalized receipts at some initial implementation cost while keeping actual browser Send/Resume proof inside Harness.

**Consequences:** One physical Owner Host controls each browser identity. Direct Harness entrypoints must honor the same lock or be disabled for Service-controlled profiles. The initial HTTP V2 surface covers only saved ChatGPT Conversations, even where Harness internally offers other providers. Do not implement a speculative second browser backend or new n8n orchestration DSL.
