# ADR-0001 — BSV2 is a Model Provider HTTP Backend

Status: **proposed**. Revised 2026-11-05; replaces the 2026-10-29 operation-first public API decision.

## Decision

Implement a standalone, OpenAI Chat Completions-compatible HTTP **model backend** on top of existing Browser Harness. Pi, OpenCode, Orca and other agents choose it through their normal model/provider configuration (`baseUrl`, API type, model ID, credentials), exactly as they would choose a compatible Ollama/vLLM server. The original agent loop owns planning, tool dispatch, continuation, and governance.

The public compatibility surface is `GET /v1/models` and `POST /v1/chat/completions`, including standard streaming behavior. BSV2 owns Browser-to-model translation; Browser Harness owns Browser/Send/Collect/Resume. Browser operations, saved conversation identities, and uncertain Attempt reconciliation are internal implementation concerns.

## Why not the former design?

The former `POST /v1/operations` → `202` → poll → Collect contract requires consumer logic. It would force a Pi Extension/Tool or per-governance wrapper and would **not** satisfy drop-in model-provider substitution.

## Consequences and trade-offs

- BSV2 stays independent of Pi, OpenCode, Orca, Queqiao, Paperclip and n8n. No agent-specific client module is required for acceptance.
- Browser-backed ChatGPT text **does not establish native model API parity**. The first ticket must prove structured tool-call and tool-result round-trip, history role fidelity and stream behavior against an actual unmodified coding agent. Lack of evidence is BLOCKED, not presumed solvable.
- The browser may only offer final text after Collect. An SSE-framed result is not a promise of real-time token streaming. Timeouts and abort semantics need actual tests.
- The standard API has no mandatory browser conversation ID or idempotency key. Internal correlation, single-send evidence and UNKNOWN fencing remain server-owned; do not impose custom required request fields.
- Keep a strict physical-profile owner lock. Preserve private target mapping and no-resend behavior in Browser Harness.
- `/v1/responses`, Anthropic Messages and other API dialects remain out of scope without separate conformance.

## Rejected alternatives

1. **Orca custom CLI adapter first:** couples Browser access to one agent runner; not reusable by Pi/OpenCode as a model provider.
2. **MCP/Agent tool first:** adds a new action into the agent loop rather than replacing its model endpoint.
3. **Operation-first public API:** suitable for operational management, but not the target model-wire interface.
4. **Plain-text pretending to be a model provider:** misses tool calls and other essential agent-loop semantics.

Keep management/diagnostics extensions separate from the primary model API; add only on proven need.
